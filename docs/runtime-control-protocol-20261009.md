# 运行控制协议补充（本地实现，待实机发布）

保留原有运动/环境/热像协议；新消息独立编号，不复用已停用的 PID 编号。所有端口、CAN can2 和 GPIO 接线保持现有配置。

## 配置下行

| 链路 | 帧内容 |
| --- | --- |
| TCP `0x40` 命令 | `[0x07, preview]` 热像偏好，`preview=0/1/2` 对应自动/常开/关闭预览；`[0x08, gear]` 全运动速度档位，`gear=0..18`，速度 `100+50*gear` |
| CAN `0x301`, sub `0x05`, DLC=8 | `[05, preview, flags, configSeq, requestEEPROM, thermalSampleSeq, 0, 0]` |
| CAN `0x301`, sub `0x06`, DLC=3 | `[06, gear, configSeq]` |
| UART `0x63`, 总长12 | `[AA,63,08,preview,flags,gear,configSeq,requestEEPROM,thermalSampleSeq,0,0,XOR]`；XOR 覆盖前11字节 |

`flags`：bit0 视觉火焰、bit1 视觉烟雾、bit2 新鲜热像热点报警、bit3 新鲜完整热像已降至45°C及以下。`thermalSampleSeq` 是完整有效图像的滚动序号；F4 消费新序号，避免用同一张旧图完成新的报警核温。视觉/远程温度标志三秒失效，手动偏好在配置心跳断流五秒后回自动。龙芯每500ms重发配置；不以发送成功代替设备确认。

## F4 状态上行

CAN `0x481` 两个8字节分段；UART 总长20：`[AA,64,10,<以下16字节>,XOR]`，XOR覆盖前19字节。多字节字段为大端。

| 分段 | 8字节内容 |
| --- | --- |
| sub `04` | `[04, state, preview, reasonHi, reasonLo, bootSecondsRemaining, gear, configSeq]` |
| sub `05` | `[05, dhtSampleSeqHi, dhtSampleSeqLo, dhtAge100msHi, dhtAge100msLo, envFlags, protocolVersion=1, 0]` |

`state=0/1/2/3` 分别为停止、启动、发送原始数据、采集故障。此字段描述 F4 实际执行，完整温度图像是否新鲜另由龙芯报告。

`reason` 位：`1`开机预览、`2`手动预览、`4`气体/烟雾、`8`物理火焰、`16`环境超温、`32`视觉火焰、`64`视觉烟雾、`128`热像热点、`256`报警后保持、`512`等待有效降温核温结果。待核温时不能仅因30秒到期关闭；新核温通过且无报警后再保持30秒。

## TCP 设备状态 `0x02`

固定27字节，原 `0x01` 的42字节传感器格式保留。新端连接不支持此状态的旧端时显示设备状态未知，自动巡检不会在速度未确认时启动。

| 偏移 | 内容 |
| --- | --- |
| 0 | 协议版本1 |
| 1 | F4 状态是否在2秒内更新 |
| 2、3 | 请求热像偏好、请求速度档位 |
| 4～19 | 原样拼接上述 F4 16字节状态；DHT 样本年龄在龙芯补计已过去时间 |
| 20～21 | 环境来源年龄，100ms单位，小端；65535=未知 |
| 22～23 | 核心遥测来源年龄，100ms单位，小端；65535=未知 |
| 24 | 是否有3秒内完整有效热像 |
| 25 | 当前请求序号 |
| 26 | 最近速度配置是否完成原子保存 |

上位机确认需同时核对状态新鲜、实际档位/偏好与请求一致、设备确认序号与请求一致。等待回读期间保持“待确认”，旧回包不覆盖刚发出的设置。TCP 速度保存使用独立 `.speed` 文件；保存失败明确显示，不能假装已经持久化。

传感器 `fault` 扩展（1.25.1）：bit0核心遥测缺失/超时，bit1环境遥测缺失/超时，bit2曾收到运行状态后状态流超时；bit3温湿度保留值可用但样本不新鲜，bit4激光保留值可用但测距无效，bit5环境来源停更但最近环境数值可用。42字节格式保持不变。

停采或来源失效时清除对应实时有效标志，保留最近有效数值。上位机显示“（保留）”，SPI 小屏用 `*` 标记；首次尚未取得有效样本时才显示无数据。热像关闭、超时及断线时保留最后一帧和温度范围，并明确显示冻结状态。保留值只用于显示，不能用于当前报警判定、解除报警核温或把设备状态标为实时正常。

## 1.25.3 追加：1500 档和平滑运动

本节替代前文速度上限 1000 的配置范围。`CMD_SPEED=0x08` 的参数扩展为 `gear=0..14`，对应 `100+100*gear`，即 100～1500、步进 100，共 15 档；默认仍为 500（gear=4）。CAN 0x301 sub06、UART AA6308 和运行状态回读使用同一档位编码，帧长度不变。非法档位大于 14 时忽略请求。主配置文件保持原样，龙芯继续用独立 `.speed` 文件原子保存速度设置。

手动驱动帧的速度范围为 -1500～1500，转向范围保持 -1000～1000。CAN、UART、摇杆、界面按钮、本地按键和自动巡检都经过实际档位限幅；旧的发送端 1000 限幅已移除。电机 PWM 载波和方向 PH 信号仍使用原来的 1000 级分辨率，不能把 PH 常量随速度档位一起改成 1500。

档位是操作配置，不是 PWM、RPM 或地面速度。F4 将档位映射为编码器单边沿脉冲/秒：目标为 `档位×12`，最高 18000 CPS；零仍立即停止。反馈保护、通道交叉配对和正反向极性修复保持。输出硬上限为 PWM=500/1000，给带载闭环留出转矩余量，实际输出由各轮反馈调节。

目标加速上限 2500 CPS/s、降档减速上限 4000 CPS/s、加速度变化上限 8000 CPS/s²；PWM 上升上限 150 单位/s、下降上限 400 单位/s。大转角目标速度连续下降，满转角最多 1800 CPS。高速突然打舵时按目标和两轮实际反馈共同限制转角，随降速渐进放开，避免减速过程中先打满舵。

CAN 0x481 sub06：`6 | target_CPS i16 BE | right_CPS i16 BE | left_CPS i16 BE | fault u8`；sub07：`7 | right_PWM i16 BE | left_PWM i16 BE | sample_ms u8 | fault u8 | version=1`。故障位：1=采样周期，2=编码器样本，4=方向，8=堵转/无反馈，16=超速。故障期间两路输出为零，收到零速度才清除锁存。42 字节传感器帧 `fault` bit6 表示运动反馈故障。

本次档位编码含义改变，运行状态协议版本由 1 改为 2（CAN 0x481 sub05 byte6 / UART 状态 byte14 / TCP 运行状态 byte18）。需要使用本次配套更新的控制程序和两端固件。
