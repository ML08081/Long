## 引脚（沿用现有龙芯连接）

| 屏幕丝印 | 龙芯IO排针/供电 | PCB LCD接口编号 |
|---|---|---|
| BLK | 外部J2的3.3V，常亮 | 8 |
| CS | 23 / SPI2_CS | 5 |
| DC | 7 / CAN2_TX复用为GPIO73 | 6 |
| RST | 9 / CAN2_RX复用为GPIO72 | 7 |
| SDA | 27 / SPI2_MO（MOSI） | 4 |
| SCL | 21 / SPI2_CK | 3 |
| VDD | 外部J2的3.3V | 1 |
| GND | 共地 / IO1、19、20或29 | 2 |

按信号丝印接线，正反面照片的左右顺序会镜像。SDA/SCL属于SPI，不接I2C。
屏幕VDD、BLK均使用3.3V；龙芯IO30的5V是开发板电源，不是屏幕电源。
保持原有 `patrol-screen-pinmux` 服务，防止原生CAN2驱动占用GPIO72/73。

## 驱动参数

- 控制器：`ST7735S`；`width=128, height=160`。
- `spi_device=/dev/spidev1.0, spi_hz=1000000, spi_mode=0`（2026-09-28板上当前配置）。
- `rotation=0, x_offset=0, y_offset=0, bgr=0, invert=1`。
- `gpio_dc=73, gpio_rst=72, gpio_bl=-1`。
- 与参考一致：RST低20ms、高120ms；01延时120ms；11延时120ms；3A=55；36=C0；21；13；29延时20ms。
- 参考GPIO模拟SPI在空闲时保持SCL高，每位先拉低、设置数据再拉高采样，初始移植使用mode 3。白屏排查期间切到mode 0；两种模式在旧的错误DC/RST配置下都白屏，不能据此断言是SPI模式导致问题。修正DC/RST后，用户已确认mode 0、MSB先发出现文字及轮播，现保持此配置。
- RGB565按高字节先发；窗口X=0..127、Y=0..159，每帧40960字节。
- 保留原类名 `St7789Display`，通过控制器配置兼容旧ST7789。新屏UI支持竖屏0/180度；90/270度拒绝启动，避免错误窗口和裁切。
- SPI设置/传输及GPIO失败会记录错误；“初始化已发送”不表示屏幕有返回确认。

## 内容与布局

1. 巡检状态（8秒）：模式、超声距离、激光距离、气体、温度、湿度、RISK及锁停/火警/气体告警。链路过期显示离线和无连接。
2. 连接状态（4秒）：上位机在线、本机IP、上位机IP及端口、连接时长。
3. 中转状态（4秒）：下位机状态、遥测/环境/热成像计数、热成像最高温度。
4. 视觉状态（4秒）：视觉名称及置信度、软件版本、运行时长。

沿用原项目16像素中文字库；长IP:port分两行，计数按uint32最大值检查。
未改变CAN、串口、摄像头、网络协议或业务控制逻辑。

## 构建、检查与部署

```bash
bash scripts/test_display.sh
python3 test/render_display.py  # 可选，需Pillow，生成测试帧预览
bash scripts/build_loong.sh
```

主机测试捕获SPI/GPIO调用，检查参考初始化命令、窗口和帧长、四页绘制、掉线状态、I/O错误和旧屏兼容；使用AddressSanitizer及UndefinedBehaviorSanitizer。
预览位于 `build-display-test/previews/pages.png`，为测试数据，不是实物截图。

先从板上下载最新 `/etc/patrol/config.json`，在构建主机上仅合并display：

```bash
python3 scripts/prepare_display_config.py board-config.json config/config.json merged-config.json
```

将新二进制、合并后的配置、`scripts/deploy_display.sh`上传板上，执行：

```bash
sh deploy_display.sh /临时目录/patrol_system /临时目录/merged-config.json <合并工具输出的原配置SHA256>
```

板上是精简Python环境，部署使用POSIX shell。仅display段变化，保留板上CAN/摄像头/串口/网络配置；SHA256核对防止覆盖下载后再次修改的配置，备份保存在 `/root/patrol-display-backups/v1.24.0-XXXXXXXX/`。
重启patrol使新二进制生效，期间控制、视频短暂停顿，服务启动后需要核查恢复。
若新服务启动失败自动恢复备份；画面方向/颜色/是否实际出图仍需实物确认。

本次Git提交只包含屏幕适配；工作树已有的未提交通信/热成像修改保留，部署继续基于用户现有完整工作树构建。
